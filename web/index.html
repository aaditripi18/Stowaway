What can hide in a model's weights that no scanner sees?

Stowaway inspects .safetensors, .pt and .gguf files for payloads in the weights, unaccounted bytes and unsafe pickle code — entirely in your browser, nothing uploaded — and shows that reading one file is not enough.

01

The problem

Model scanners such as picklescan and ModelScan look for code hidden in pickle data, and converting a model to .safetensors removes code entirely — so safetensors files are trusted by default.

But a payload does not need to be code. It can sit in the low bits of the weights, in bytes appended after the last tensor, or in alignment padding. It survives format conversion because it is just numbers, and a loader that later pulls it out and runs it is small enough to live anywhere. Stowaway looks where the code scanners do not, and measures how much can hide before anything notices.

02

What it checks

S1

Pickle imports

Unsafe code in pickle data, found by a restricted unpickler and an opcode walk. Nothing is ever executed.

S2

Byte coverage

Every byte must belong to a header, a tensor or zero padding. Anything else is reported with its offset.

S3

Precision history

Low bits that should be zero — e.g. fp16 or bf16 weights saved as float32 — but are not.

S4

Bit-plane statistics

Low bits pulled toward a fair coin, measured against the tensor's role peers in the same model.

S5

Base-model diff

A bit-level diff against the claimed base model: changes confined to the low bits are a payload, not training.

Formats are detected from content, never the extension: safetensors, PyTorch zip (.pt/.pth/.bin), plain pickle and GGUF.

03

The experiments

A payload is just numbers. It survives conversion to a "safe" format, costs the model nothing measurable, and no code scanner looks at it. So the question is which models give it away from the file alone.

Where a random payload hides, by what the model's weights look like
What the weights look like Models Payload seen from the file alone
float32 file carrying only fp16 or bf16 precision 14 14 / 14 at every k
float32 with a low-bit signature 2 2 / 2 at every k
float32 with fair-coin low bits 23 0 / 23 at every k

The 40 most-downloaded non-gated float32 safetensors models on Hugging Face (39 had testable samples); random bytes in the low k = 1, 4 or 8 bits of one sampled tensor. For 23 of 39, a clean single-file scan certifies nothing about the weights.

04

What one file can't see

Random bytes in ResNet-18's low 8 bits, up to 4 MB, leave top-1 accuracy exactly unchanged and pass both single-file checks at every size tested. Only a bit-for-bit diff against the base model catches them.

MobileNetV3-Small's low bits carry a signature (bit 0 set in ~67% of values) that a random payload disturbs, so the naive attack is seen from the file. An attacker who knows the checks can still evade them: spreading the payload over one weight in 64 keeps every statistic inside the threshold at every size up to 1 MB. The base diff catches that from 4 KB.

05

Four hypotheses

H1
S1 matches picklescan on code payloads, and every weight-payload model passes picklescan and a safetensors conversion untouched. Evidence: not yet run. The side-by-side with picklescan and ModelScan is experiment E5, scheduled for the remaining weeks.
Not yet tested
H2
In a model stored at higher precision than it was trained in, a payload of 1 KB or more is caught by S3 with no false positives. Evidence: on 19 real bf16 models widened to float32, S3 identified bf16 precision in 19 / 19, raised 0 false positives, and caught a 1 KB payload in 19 / 19 at k = 1, 4 and 8.
Supported
H3
In a genuinely float32-trained model, an encrypted low-bit payload cannot be seen from one file. Evidence: true for the 23 of 39 surveyed models with fair-coin low bits and for ResNet-18; false for the 2 with a low-bit signature, such as MobileNetV3-Small.
Model-dependent
H4
A diff against the claimed base model catches a payload in any tensor the fine-tune did not train. Evidence: caught in 10 / 10 held-out pairs for payloads in the low k = 8, 16, 20 and 21 bits. Limits: a payload inside a tensor the fine-tune did train is camouflaged (0 / 10), and a 1 KB payload spread at 1:64 stays under S5's per-tensor floor.
Supported, with limits

Hypotheses were written before any experiment ran (PLAN.md).

06

What we learned

A clean scan is not a clean model.

For most popular float32 models, single-file statistics have no signal: a payload thin enough moves no number far enough. The check that does not depend on where the bytes go needs the trusted base model to diff against.

Whether one file is enough depends on the model.

Some models' low bits are fair coins that hide anything; others carry a signature a payload disturbs. We measure which, rather than assume.

A third of "float32" uploads are really half precision.

14 of 39 top models are saved as float32 but hold only fp16 or bf16 precision, leaving a block of zero low bits — exactly where a payload would go, and exactly where S3 sees it.

The strong check has a blind spot too.

A payload confined to tensors the distributor genuinely trained is camouflaged by the training, so even the base diff misses it. We report the limit rather than hide it.

07

Validated on unseen models

0 S5 false positives

on 15 held-out honest fine-tune / base pairs (RoBERTa, XLM-R and ViT fine-tunes).

10 / 10 S5 detections

held-out pairs where S5 caught a payload in a tensor that should match the base, at k = 8, 16, 20 and 21.

5 → 1 of 20 S4 false-positive models

on a fresh batch of bf16 models, first revision of S4 against the current rule (and 1 → 0 of 20 for fp16).

Each detector was frozen, then run once on a batch of models committed before their weights were read, so these numbers were not tuned on the models they describe.

08

Reproduce

from a clone of the repo
# install and run the 106 Python tests $ pip install -e ".[dev]" && python -m pytest # scan one file (exit status: 0 clean, 1 suspicious, 2 dangerous) $ python -m stowaway scan model.safetensors # add the S5 diff against the claimed base model $ python -m stowaway scan finetune.safetensors --base base.safetensors # the Hugging Face survey (range requests, no full downloads), then regenerate RESULTS.md $ python scripts/run_hf_survey.py --list hf_models.json $ python scripts/report.py

Nothing is trained: models are downloaded pretrained and only run forward. Every run appends to results/ledger.jsonl with the git commit that produced it, and docs/RESULTS.md is generated from that ledger, never edited by hand. 146 tests: 106 Python, and 40 for the browser build, including parity tests that require byte-identical JSON reports to the Python tool on every fixture.

09

Limitations

  • /These are preliminary results: two vision models end to end, one seed, and random payloads only.
  • /Single-file statistics cannot see a small or thinly spread encrypted payload in a fair-coin model.
  • /The base diff needs the real base model, and misses a payload inside a tensor the fine-tune genuinely trained.
  • /The survey tests 64 KB samples, not whole files, and is weighted to the most downloaded models, not a random sample.
  • /Legacy (pre-1.6) torch files and compressed zip entries are read by the command-line tool, not the browser.
